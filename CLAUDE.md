# Bus Spike — BeyondSchools School Bus Safety Platform

@AGENTS.md

## What this repo is

A one-week **technical spike** for the bus app of the BeyondSchools School Bus
Safety Platform. It is throwaway code that answers three risk questions before
the real build starts:

1. **Background GPS:** does a cheap Android tablet keep sending its position
   every ~10 s for a 90-minute trip with the screen off?
2. **Turn-by-turn:** does `@googlemaps/react-native-navigation-sdk` (Beta) work
   inside our Expo app on React Native 0.88 (the package is tested on 0.87)?
3. **Offline queue:** do events recorded with no signal arrive once, and only
   once, when the signal returns?

Pass criteria are in `README.md` → "Test checklist". When all pass, the spike
is done; findings go into the plan doc, and the real app starts in a new repo.

## Who you're working with

Datius knows React, TypeScript and FastAPI well. He is **new to React Native
and Android**. He reviews and must understand every change.

Rules for every change:
- **Small steps.** One concern per change. Stop and let him run it.
- **Explain RN/Android specifics in comments** where they differ from React on
  the web (no DOM, `<View>`/`<Text>`, StyleSheet, native modules, foreground
  services, permissions, the JS task lifecycle). Plain React needs no comment.
- **Nothing he can't explain gets merged.** If he asks "why", answer in the
  code comment, not only in chat.
- Never edit `android/` by hand — it is generated by `npx expo prebuild` from
  `app.config.ts` and config plugins (see AGENTS.md).

## Layout

```
index.ts                 Entry. Imports src/location/task FIRST (task must be defined at load).
app.config.ts            Native config + plugins. API key and server URL come from .env.
src/db/db.ts             On-device SQLite: gps_point, trip_event, each with synced flag.
src/location/task.ts     Background location task (foreground service) → SQLite → trySync().
src/sync/uploader.ts     POST unsynced rows to the server; mark synced only after 2xx.
src/nav/NavScreen.tsx    Google Navigation SDK through TEST_STOPS; arrivals logged as events.
src/ui/HomeScreen.tsx    Start/stop GPS, counters, test event, sync now.
src/ui/theme.ts          Colours from the design canvas.
server/main.py           FastAPI receiver: idempotent /spike/batch, /spike/stats with gap report.
```

## Commands

```bash
npm install
npx tsc --noEmit                                   # typecheck (must pass)
npx expo prebuild --platform android --clean       # regenerate android/ after config changes
npx expo run:android                               # dev build on a USB-connected tablet
cd server && uvicorn main:app --host 0.0.0.0 --port 8000
```

Known setup facts (verified when the spike was scaffolded):
- Expo SDK 58, React Native 0.88.1, Navigation SDK package 0.19.1.
- `expo-build-properties` sets `kotlinVersion: '2.3.21'` — the Navigation SDK
  needs Kotlin 2.3+, RN 0.88 ships 2.2.0. Don't remove it.
- The Navigation SDK config plugin fails prebuild if
  `android.config.googleMaps.apiKey` is empty — set `GOOGLE_MAPS_API_KEY` in `.env`.
- Expo Go cannot run this app (native modules). Always use a development build.

## Decisions already made (don't relitigate in the spike)

- Bus app: React Native + Expo, Android first. One app with driver and
  conductor modes.
- Backend: FastAPI + PostgreSQL/PostGIS + Redis + Celery (same layered
  structure as the BeyondSchools SMS repos).
- Every parent gets SMS for every trip event; push is extra.
